================================================================================
  TEXTO PARA PEGAR EN LA IA DEL PROYECTO DE MAPAS (RIDERS)
================================================================================

Contexto: La tienda Aqua (Next.js + Postgres) administra cuentas de repartidores
en la tabla "Rider". La app de mapas NO debe conectarse con DATABASE_URL ni leer
el resto de la base. Solo debe usar la API HTTP pública de Aqua.

IMPORTANTE: Los riders solo manejan compras MINORISTAS (retail) con envío a
domicilio. Los pedidos mayoristas NO usan esta app: los gestiona el empleado.

--------------------------------------------------------------------------------
1. VARIABLES DE ENTORNO EN LA APP DE MAPAS (solo estas)
--------------------------------------------------------------------------------

AQUA_API_BASE_URL=https://tu-dominio-aqua.up.railway.app
   (en local: http://localhost:3000)

NO uses DATABASE_URL de Aqua.
NO uses NEXTAUTH_SECRET de Aqua en el cliente.

Opcional en el servidor de la app mapas (si validás JWT localmente):
RIDER_JWT_SECRET=<mismo valor que en Railway del backend Aqua, solo en backend del mapa>

--------------------------------------------------------------------------------
2. AUTENTICACIÓN DEL RIDER
--------------------------------------------------------------------------------

LOGIN
  POST {AQUA_API_BASE_URL}/api/riders/auth/login
  Content-Type: application/json
  Body: { "email": "rider@ejemplo.com", "password": "su_clave" }

  Respuesta 200:
  {
    "token": "<JWT>",
    "rider": {
      "id": "cuid...",
      "riderNumber": 1,
      "name": "Nombre",
      "email": "rider@ejemplo.com",
      "phone": "+54..."
    }
  }

  riderNumber es el número visible (#001) que el vendedor usa para asignar viajes en Aqua.

PERFIL
  GET {AQUA_API_BASE_URL}/api/riders/me
  Header: Authorization: Bearer <token>

  Respuesta 200:
  { "rider": { "id", "name", "email", "phone", "isActive" } }

--------------------------------------------------------------------------------
3. ENTREGAS MINORISTAS (envío a domicilio)
--------------------------------------------------------------------------------

LISTAR ENTREGAS PENDIENTES
  GET {AQUA_API_BASE_URL}/api/riders/deliveries
  Header: Authorization: Bearer <token>

  Respuesta 200:
  {
    "deliveries": [
      {
        "orderId": "clxabc123...",
        "buyerName": "María García",
        "phone": "+5491123456789",
        "email": "maria@ejemplo.com",
        "address": "Av. Corrientes 1234, CABA, CABA · CP 1043",
        "postalCode": "1043",
        "deliveryStatus": "DISPATCHED",
        "deliveryStatusLabel": "En camino",
        "dispatchedAt": "2026-05-20T15:30:00.000Z"
      }
    ]
  }

  Solo pedidos minoristas DISPATCHED asignados a ESE rider (assignedRiderId).
  El código de 4 dígitos NO viene en esta respuesta: lo dicta el cliente al recibir.
  Si la lista está vacía, el vendedor aún no asignó viajes a este repartidor en /vendedor/envios.

CONFIRMAR ENTREGA
  POST {AQUA_API_BASE_URL}/api/riders/deliveries/confirm
  Header: Authorization: Bearer <token>
  Content-Type: application/json
  Body: { "orderId": "clxabc123...", "code": "4829" }

  Respuesta 200: { "ok": true }
  Errores: 400 datos inválidos, 403 código incorrecto, 404 no encontrado, 409 no pendiente.

--------------------------------------------------------------------------------
4. ESCANEO DE QR EN EL TICKET DE ENVÍO
--------------------------------------------------------------------------------

El QR contiene un JSON (snapshot al imprimir). Usar address, fullAddress o direccion
(tienen el mismo texto). Validar shippingMethod === "DELIVERY" antes de exigir dirección.

  {
    "v": 1,
    "type": "retail",
    "orderId": "clxabc123...",
    "buyerName": "María García",
    "phone": "+5491123456789",
    "email": "maria@ejemplo.com",
    "shippingMethod": "DELIVERY",
    "address": "Av. Corrientes 1234, CABA, CABA · CP 1043",
    "fullAddress": "Av. Corrientes 1234, CABA, CABA · CP 1043",
    "direccion": "Av. Corrientes 1234, CABA, CABA · CP 1043",
    "postalCode": "1043",
    "riderNumber": 2,
    "riderId": "cuid..."
  }

  En envíos a domicilio, riderNumber y riderId son OBLIGATORIOS en el QR (el vendedor asigna
  repartidor ANTES de imprimir el ticket). Si el rider logueado no coincide con riderNumber
  del QR, NO debe poder abrir el viaje.

  Si shippingMethod es PICKUP, riderNumber puede ser null (no es entrega de rider).

Tras escanear el QR, validar con la API de riders (NO uses solo el JSON del QR):

  GET {AQUA_API_BASE_URL}/api/riders/orders/{orderId}?riderNumber={del QR}
  Header: Authorization: Bearer <token del login>

  Respuesta 200: datos del pedido + riderNumber/riderName confirmados.
  Respuesta 403: "Este viaje está asignado al repartidor #00X" — mostrar error y no permitir tomar.

  Alternativa pública (sin validar rider):
  GET {AQUA_API_BASE_URL}/api/shipping/orders/{orderId}?type=retail

  Respuesta 200 (ejemplo completo para la pantalla de entrega):

  {
    "v": 1,
    "type": "retail",
    "orderId": "clxabc123...",
    "buyerName": "María García",
    "phone": "+5491123456789",
    "email": "maria@ejemplo.com",
    "shippingMethod": "DELIVERY",
    "shippingMethodLabel": "Envío a domicilio",
    "status": "CONFIRMED",
    "statusLabel": "Confirmado / listo",
    "address": "Av. Corrientes 1234, CABA, CABA · CP 1043",
    "fullAddress": "Av. Corrientes 1234, CABA, CABA · CP 1043",
    "direccion": "Av. Corrientes 1234, CABA, CABA · CP 1043",
    "postalCode": "1043",
    "customerComments": "Tocar timbre 3B · Dejar en portería",
    "deliveryStatus": "DISPATCHED",
    "deliveryStatusLabel": "En camino",
    "riderNumber": 2,
    "riderId": "cuid...",
    "riderName": "Juan Pérez",
    "createdAt": "2026-05-20T18:30:00.000Z"
  }

  Nunca incluye deliveryCode. Solo deliveryStatus indica si se puede confirmar:
  - PENDING = aún no salió
  - DISPATCHED = en camino, pedir código al cliente
  - DELIVERED = ya entregado

--------------------------------------------------------------------------------
5. FLUJO RECOMENDADO
--------------------------------------------------------------------------------

1. Login → guardar token JWT
2. GET /api/riders/deliveries → lista / mapa de entregas
3. Escanear QR → comparar qr.riderNumber con sesión → GET /api/riders/orders/{id}?riderNumber=N
4. Al llegar: pedir código de 4 dígitos al cliente
5. POST /api/riders/deliveries/confirm con { orderId, code }

--------------------------------------------------------------------------------
6. RESUMEN PARA LA IA
--------------------------------------------------------------------------------

Implementá la app de riders solo para compras minoristas con envío a domicilio.
Endpoints permitidos:
  POST /api/riders/auth/login
  GET /api/riders/me
  GET /api/riders/deliveries
  POST /api/riders/deliveries/confirm
  GET /api/shipping/orders/{id}?type=retail

Prohibido: Prisma, DATABASE_URL, pedidos mayoristas, APIs de admin o tienda.
